## Lessons that cost real work — do not repeat these

- **Check whether your finding is circular before you build the project on it.** NIRF *publishes* the weights that R1 "discovered" by least squares. The residual was 0.007 — rounding. Two full review rounds were spent on a project whose core question had an answer sitting in NIRF's own methodology PDF. **Before proposing a forensic project, ask whether the answer is already published.**
- **Verify the replacement, not just the original.** I "corrected" a false Jordan-block identity into a *different* false identity (`nullity(Aᵏ)` = blocks of size ≥ k). The correct form is the first difference, `nullity(Aᵏ) − nullity(Aᵏ⁻¹)`. A correction you have not re-verified is a second bug, not a fix.
- **Do not assert a numerical property of a dataset you have not measured.** "NIRF's five indicators are collinear" was assumed, never measured. They are not: `rank = 5`, `nullity = 0`, condition number 4.89, max off-diagonal correlation 0.769. That one unmeasured assumption was propping up a "9–10 CORE stages" score.
- **An identity that holds for every object in the class carries no information.** `nullity(Xᵀ) = 195` is true of any full-rank 200×5 matrix, and "which rows lie in the span of the others" is true of all of them by construction. A stage that cannot fail cannot find anything.
- **An adversarial reviewer's findings are evidence, not verdict.** Run 2's reviewer reported PESU's fee as ₹5,50,000; `pes.edu/fee` says ₹5,70,000 — the 5,50,000 was last year's published figure, stale rather than fabricated. Two of three blockers were real, one was wrong. **Verify before you correct anything.**
- **"College-oriented" overpromises.** What exists publicly is higher-education *statistics*, not campus life. Campus-life data (attendance, timetables, mess, hostels, transport) is not public.
- **Check the DENOMINATOR before you headline a coefficient of determination.** The inherited build audit, handoff and spec all reported `R² = 0.0214` — computed as `1 − SS_res/‖b‖²`, an **uncentred** total sum of squares. The standard centred value is **−0.2103**. Both are arithmetically correct; only one is the coefficient of determination, and quoting the other hides a negative. `diagnostics.r_squared` now takes `centred` as a **keyword-only argument with no default**, so the ambiguous call is not possible.
- **A negative fit statistic can be structural, not statistical — check the design matrix before you blame the data.** `R² = −0.2103` was presented as a finding about noise. It is arithmetic: `A @ 1 = 0` exactly, so `A x` has mean zero while `mean(b) = +18.04`, and the fit sits **17.30 runs low on every one of the 558 matches**. Adding the one constant column `A` was never allowed moves centred R² to **+0.0181** — a real improvement, still no signal. The project's own stage 4 (rank deficiency ⇒ only differences identifiable) *is* the cause of stage 8's negative number. **When a model underperforms, verify it was even allowed to succeed.**
- **Compare like with like, or the ratio is meaningless.** "SNR ≈ 0.19" and "noise is five times the signal" came from `std(b)` over `std(x)` — a **data** spread over a **coefficient** spread. The defined quantities are `||r||/√m = 40.79` against `std(A x) = 5.98`, ratio **6.82**. Both old numbers were real; the ratio between them was not.
- **The baseline you compare against decides whether your model looks good.** Winner accuracy was reported against a 50% coin flip. The majority-class baseline is **77.96%** (the first-listed team won 435 of the 558), so 55.02% is **negative skill**. Choosing the weaker comparator flattered the result. Always name the trivial predictor that matters.
- **A comparison across two conventions silently drops rows.** This exact error happened *twice in one session*: comparing canonical `team1` against the **raw** `winner` string scored 88 renamed-franchise wins as losses and gave 62.19% instead of 77.96%. It was then published in a "correction" that accused a correct reviewer of being wrong. **The lesson `verify the replacement, not just the original` was violated by the document quoting it.** `diagnostics.majority_class_accuracy` now *requires* the two conventions to agree and raises if they drift.
- **An over-broad quantifier is a false claim even when the number is right.** "1 component … and per-season" survived two reviews. Measured: over all 15 franchises a single season's graph has **6–8 components** (franchises that did not play are isolated); among the teams **active** that season it is 1, in all 19 seasons. The rank inference is unaffected — the design matrix is pooled — but the phrase was withdrawn. **Qualify the quantifier, keep the inference.**
- **A guard that restores itself before the run is cosmetic.** `--offline` installed the import/socket block, printed "blocked", and restored both hooks **inside the same function** — before `run_demo` ran. A fetch during the run would have succeeded, and the exit-1 path was dead code, while three docstrings and the README promised otherwise. Now held for the whole run, restored in a `finally`, and pinned by a test that reaches for `urllib.request` *during* the run and asserts exit code 1.
- **A file that claims something is committed, while nothing is committed, is an overclaim.** `.gitignore` asserted `data/matches.csv` was committed; `git ls-files -- data` was empty and the repository had **zero commits**. The demo's only input was untracked. Check the claim against the repository, not against intent.
- **Do not let a tool round-trip a UTF-8 file.** A PowerShell `Get-Content -Raw | Set-Content -Encoding utf8` pass double-encoded every em-dash and `R²` in `README.md` and added a BOM. Repaired by reversing the encoding (`utf-8 → cp1252 → utf-8`); use the editor tools instead.
- **Batch-correct your narration when a headline number changes.** After the intercept correction, six places still told the old story — the terminal, the report's findings block, the R² table, a figure caption, the module docstring and the closing summary. A retracted claim left in one of them is worse than the original error, because the project now contradicts itself. Both R² values and the majority baseline are now asserted **present** in the demo output by a test, and the retired phrases (`five times`, `SNR 0.19`, `worse than a coin flip`) are asserted **absent**.
